# ESPaperPlay v2 实施路线与验收

设计基线见 [architecture.md](architecture.md)。硬件保持 S3-WROOM-1-N16R8、16 MB Flash、8 MB PSRAM 和现有 7.5 英寸屏幕，新主板独立推进。

本路线区分设计决定、代码交付与实机验收。阶段通过必须有相应的测试或测量记录；编译成功不能代替上板验证。实际完成情况以当前工程说明和检查输出为准。

## M0：可构建的平台基础

**本轮交付范围。** 新工程在 `v2/` 独立构建，旧版在[原仓库固定提交](https://github.com/xiaobaoaaaaaa/ESPaperPlay/tree/0f6d7c349afdbbeb962a736d84036ce7f8487174)保留为迁移参考。此阶段是串口启动骨架，不包含真实图形应用、音频播放、联网、芯片休眠或完整 OTA 客户端。

| 工作项 | 交付物 | 验收证据 |
| --- | --- | --- |
| 固化设计 | 软件架构、硬件 GPIO／电源域／功耗预算表 | 明确现有事实、候选方案和待测数值 |
| 可移植运行时 | 静态应用注册与切换、实例代号 | 主机测试验证非法目标、切换失败恢复、过期结果拒绝 |
| 活动与休眠协调 | 有界活动租约、准备／恢复回调 | 容量、无效／重复句柄、准备失败逆序回滚测试 |
| 板级描述 | N16R8 与现有板级约束的元数据 | 不把新板待定 GPIO 当成可执行硬件配置 |
| 固件入口 | ESP-IDF 串口启动与运行时演示 | ESP32-S3 交叉编译成功，产物可重复生成 |
| Flash 规划 | 16 MB 双 OTA 槽分区原型 | 分区无重叠且满足对齐；固件容量检查 |
| 自动检查 | 主机测试与固件构建工作流 | 本地检查通过；远端 CI 状态在推送后单独记录 |

M0 不连接或操作未经确认的新板 GPIO。若没有进行烧录，报告必须明确“已构建、未上板”。仅有 OTA 槽不表示下载、健康确认、回滚和分区迁移已经完成。

## M1：显示、输入与两个前台应用

目标是用最小真实界面验证应用边界，而不是先完成一个大型阅读器。

- 接入板级配置、EPD、GT911 和按键，保留旧驱动中已验证的时序并单独回归。
- 接入 LVGL 与唯一 UI 所有者任务，统一方向、输入、状态栏与模态层。
- 实现显示服务的提交、缓冲所有权、刷新完成和错误恢复流程。
- 提供两个小型应用，例如文本浏览和设备信息；应用切换经过共同生命周期入口。
- 验证页面销毁后的异步结果丢弃、内存回收，以及失效显示状态的恢复。

验收：实板完成连续切换、输入、局刷／全刷／灰阶和旋转测试；记录端到端刷新时间、内存峰值与栈水位。UI 模拟器可以检查布局，但不能证明面板残影、时序或耗电正确。

## M2：后台音频与网络组合验证

这是验证多功能平台架构的关键阶段。

- 使用有界缓冲实现 PCM/WAV 播放，音频会话独立于前台页面。
- 增加基础联网请求、一个下载或数据刷新任务，并定义超时与取消。
- 存储服务实现挂载状态、文件使用协调和长 I/O 分块。
- 增加可观察的音频欠载、网络重试、队列满载与缓存回收指标。

组合验收必须覆盖：

1. 播放持续运行时切换两个前台应用，播放会话保持有效。
2. 播放期间刷新电子纸和更新网络数据，记录音频欠载与输入延迟。
3. 页面退出取消页面请求，持续下载或播放会话按约定继续。
4. 网络断开、文件错误、缓冲不足能报告失败并释放资源。
5. 请求删除或覆盖正在播放的文件得到可解释的结果，避免静默破坏使用者。

音频压缩格式和同时录放在基本管线稳定后逐项加入。是否通过并发验收由真实采样率、音频格式和实际网络／SD 条件决定。

## M3：休眠、唤醒与状态恢复

- 将运行时租约和休眠协商连接到实际服务及 ESP-IDF 电源管理。
- 明确每种运行模式的唤醒源、保留电源域与待处理任务。
- 保存内容位置和服务状态；深睡后通过启动流程恢复。
- 在准备失败、活动冲突或新输入到来时，取消休眠并恢复服务。

验收至少包含音频活动、SD 写入、显示 BUSY、联网任务阻塞休眠的场景；成功入睡后的按键／触摸／定时唤醒按所选板卡能力分别测试。验证旧板共轨限制与新板独立电源域的差异，不能使用同一组假设。

功耗记录区分面板保留画面、触摸待机、MCU 浅睡与深睡；记录测量接入位置、供电电压、外设状态和固件版本，不提前给出整机续航承诺。

## M4：应用能力与可靠升级

- 迁移阅读器解析与布局测试，接入新文档／排版接口；阅读历史改为内容锚点与版本化恢复。
- 加入相册、录音、天气等应用，复用平台服务和通用交互。
- 本机与 Web 管理共用业务命令，完成认证、文件操作和后台任务状态展示。
- 实现 OTA 下载、镜像校验、启动健康确认及失败回滚。
- 验证设置、基础资源与固件回滚的版本兼容；制定旧分区／旧数据首次迁移方案。

验收包括损坏文档、大图片、SD 拔出、网络长时间失败、重要状态写入时断电，以及 OTA 各阶段断电与启动失败。FAT 文件发布与重要记录恢复分别验证，不以一次正常重启代替故障测试。

## 检查分工

| 检查环境 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 主机 C 测试与 sanitizers | 生命周期、句柄、解析、缓存与错误路径的内存／逻辑行为 | FreeRTOS 调度、外设时序与整机功耗 |
| ESP-IDF 构建 | 目标工具链、组件依赖、API 兼容、镜像与分区容量 | 固件实际启动、PSRAM 稳定性、硬件功能 |
| UI 模拟器 | 页面结构、基本布局与交互状态 | 电子纸刷新、残影与触摸电气问题 |
| 实板组合测试 | 输入、显示、音频、网络、存储和电源共同工作的表现 | 不同板卡／温度／电池条件下未经测试的结论 |

每轮只新增与当前阶段有关的实现和测试。动态安装应用、脚本虚拟机、多窗口系统及额外无线音频硬件均不属于当前基线。
